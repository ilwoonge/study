Pattern

Backtracking

Backtracking explores possible choices recursively. When a path cannot lead to a valid answer, the algorithm stops that path and returns to try another choice.

Backtracking Mental Model

1. Make a choice.
2. Continue with that choice.
3. If the path is complete, save it.
4. If the path is invalid, stop early.
5. Go back and try another choice.

This is useful when the answer is a list of combinations, permutations, subsets, or valid arrangements.

Generate Parentheses Rules

"("Add it only when open_count < n.
")"Add it only when close_count < open_count.
doneSave the string when its length is 2 * n.

Why Invalid Paths Are Blocked

n = 3

"(((" has open_count = 3

Can we add another "("?
open_count < n
3 < 3  -> False

So "((((" and "((((((" cannot be created.

The algorithm does not wait until the end to reject every bad answer. It uses rules during recursion to avoid creating many invalid strings in the first place.

LeetCode 22

Generate Parentheses

Build the string one character at a time. At every step, choose whether adding an opening or closing parenthesis is still valid.

Python Solution

Backtracking 
def generateParenthesis(n):
    result = []

    def backtrack(current, open_count, close_count):
        if len(current) == 2 * n:
            result.append(current)
            return

        if open_count < n:
            backtrack(current + "(", open_count + 1, close_count)

        if close_count < open_count:
            backtrack(current + ")", open_count, close_count + 1)

    backtrack("", 0, 0)
    return result

Complexity

The number of valid answers grows quickly as n grows. For interviews, it is usually enough to explain that the algorithm generates only valid parenthesis combinations and each saved string has length 2n.

Interview Sentence

"I use backtracking because I need to generate every valid combination. I track how many opening and closing parentheses have been used. I only add an opening parenthesis if I still have one available, and I only add a closing parenthesis if it would not make the string invalid."

System Design

Database Sharding and Partitioning

Sharding splits data across multiple database machines. This helps when one database can no longer store or serve all the data by itself.

Replication vs Sharding

Replication:
copy the same data to multiple databases

Sharding:
split different data across multiple databases

Replication helps scale reads and improve availability. Sharding helps scale storage and write volume by dividing the dataset.

Simple Sharding Example

User ID 1-1000     -> Shard A
User ID 1001-2000  -> Shard B
User ID 2001-3000  -> Shard C

The application uses a partition key, such as user_id, to decide which shard stores or serves a record.

Choosing a Partition Key

Good keyDistributes traffic and data evenly.
Bad keyCreates hot shards that receive too much traffic.
Exampleuser_id is often better than a low-cardinality field like country.

Tradeoffs

Sharding improves scale, but it makes cross-shard queries, transactions, joins, and rebalancing more complex. 

Benefits:
- More storage capacity
- More write throughput
- Smaller indexes per shard

Costs:
- Harder joins
- Harder transactions
- Hot shard risk
- Rebalancing complexity

Must-Memorize Q&A

Concepts You Should Be Able to Say Out Loud

What is backtracking?

Backtracking is a recursive pattern that tries choices, continues when the path is valid, and returns to try another choice when needed.

Why does Generate Parentheses use backtracking?

Because the problem asks for all valid combinations, and each step has controlled choices: add ( or add ).

Why can we add ( only when open_count < n?

Because a valid answer must use exactly n opening parentheses. This prevents strings like "((((((" when n = 3.

Why can we add ) only when close_count < open_count?

Because a closing parenthesis must match a previous opening parenthesis. Otherwise the current string becomes invalid.

What is sharding?

Sharding splits different parts of a dataset across multiple databases so the system can scale storage and write traffic.

What is the difference between replication and sharding?

Replication copies the same data to multiple machines. Sharding splits different data across multiple machines.
