Concepts

Big-O and Data Structure Intuition

Big-O describes how an algorithm's running time grows as the input size n gets larger.

Big-O Quick Map

O(1) Constant time, independent of input size
O(n) Linear time, usually one full scan of the input
O(n log n) Commonly appears when sorting is involved

Array Index Access

Arrays store elements in contiguous memory. If you know the index, the computer can calculate the exact address directly, so index access is O(1).

10 20 30 40 
address = base + index * element_size

HashMap Lookup

A HashMap passes a key through a hash function to calculate where the value should live. That is why lookup and insertion are average O(1).

"apple" -> bucket 7

In the worst case, collisions can make lookup O(n), but in interview analysis we usually use the average case, O(1).

Array vs HashMap

Need Good Choice Why
Index access Array The address can be calculated directly.
Value lookup HashMap / Set Existence can be checked in average O(1).
Count frequency HashMap A count can be stored for each key.

LeetCode 1

Two Sum

The key question is: "Have I already seen the value that completes the current number to the target?"

HashMap Solution

Time O(n) / Space O(n) 
def two_sum(nums, target):
    seen = {}

    for i, num in enumerate(nums):
        need = target - num

        if need in seen:
            return [seen[need], i]

        seen[num] = i

seen stores each number as the key and its index as the value. We check for the needed value before storing the current number so we do not accidentally use the same element twice.

LeetCode 2

Contains Duplicate

If you only need to know whether a value has appeared before, and you do not need its index or count, a Set is the natural tool.

Set Solution

Time O(n) / Space O(n) 
def contains_duplicate(nums):
    seen = set()

    for num in nums:
        if num in seen:
            return True

        seen.add(num)

    return False

HashMap vs Set

Two Sum needs the index, so it stores number -> index in a HashMap. Contains Duplicate only needs existence, so a Set is enough.

Interview Sentence

"To detect duplicates, I keep a Set of previously seen numbers. For each number, I check whether it already exists in the Set. Since Set lookup and insertion are average O(1), the total time complexity is O(n), and the space complexity is O(n)."

Must-Know Q&A

Questions You Should Be Able to Answer

These are the core interview-style questions from Day 1. Practice answering them out loud.

What does Big-O notation describe?

Big-O describes how an algorithm's time or space requirement grows as the input size gets larger. It focuses on growth rate, not exact runtime in seconds.

What is the difference between O(1), O(n), and O(n log n)?

O(1) stays constant regardless of input size. O(n) grows linearly with the input. O(n log n) is usually associated with efficient sorting algorithms and grows faster than O(n) but much slower than O(n^2).

Why is array index access O(1)?

Arrays store elements contiguously in memory. Given a base address, element size, and index, the computer can calculate the exact address directly using base + index * element_size.

Why is searching for a value in an array O(n)?

If you only know the value and not the index, you may need to scan every element until you find it. In the worst case, that requires checking all n elements.

Why is HashMap lookup average O(1)?

A HashMap uses a hash function to convert the key into a bucket location. In the average case, this lets the program jump directly to the expected location instead of scanning all entries.

When should you consider using a HashMap?

Use a HashMap when you need fast lookup, need to remember values you have already seen, need to map one value to another, or need to count frequencies.

What does the HashMap store in Two Sum?

It stores each number as the key and that number's index as the value. This allows us to return indices when we find the needed complement.

Why do we check before inserting in Two Sum?

Checking first ensures that the complement comes from a previous element. This avoids using the same element twice when num + num == target.

Why use a Set for Contains Duplicate?

The problem only asks whether a number has appeared before. Since we do not need an index or count, a Set gives the simplest average O(1) existence check.

What are the time and space complexities of both solutions?

Two Sum is O(n) time and O(n) space. Contains Duplicate is also O(n) time and O(n) space because each solution scans the input once and may store up to n values.
