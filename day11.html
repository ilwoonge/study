Data Structure Pattern

Monotonic Stack

A monotonic stack keeps values or indexes in a controlled increasing or decreasing order. It is useful when a problem asks for the next greater, next smaller, warmer, colder, or closer value.

Normal Stack vs Monotonic Stack

Normal stackStores recent items using LIFO.
Monotonic stackStores unresolved items while preserving a useful order.

Common Signal

If the question says "next greater element" or "how many days until a greater value appears," think about a monotonic stack. 

Example questions:
- Next warmer day
- Next greater number
- Stock span
- Remove values while current value resolves previous values

Why Store Indexes?

Many monotonic stack problems need distance, not just the value. Storing indexes lets us calculate current_index - previous_index.

LeetCode 739

Daily Temperatures

For each day, return how many days you must wait until a warmer temperature. If no warmer day exists, return 0 for that day.

Example

temperatures = [73, 74, 75, 71, 69, 72, 76, 73]

answer       = [ 1,  1,  4,  2,  1,  1,  0,  0]

Day 2 has temperature 75. The next warmer temperature is 76, which appears 4 days later.

Optimized Solution

Time O(n), Space O(n) 
def dailyTemperatures(temperatures):
    answer = [0] * len(temperatures)
    stack = []

    for i, temp in enumerate(temperatures):
        while stack and temp > temperatures[stack[-1]]:
            prev_index = stack.pop()
            answer[prev_index] = i - prev_index

        stack.append(i)

    return answer

Core Line

while stack and temp > temperatures[stack[-1]]:

If today's temperature is warmer than the unresolved day on top of the stack, today's index is the answer for that previous day.

Why O(n)?

Each index is pushed once and popped at most once. Even though there is a while loop, the total number of stack operations is linear.

Interview Sentence

"I keep a stack of indexes whose warmer day has not been found yet. When the current temperature is warmer than the temperature at the stack top, I pop that index and fill in the waiting days."

System Design Basics

SQL vs NoSQL

Database choice depends on access patterns, consistency needs, relationships, transaction requirements, and expected scale.

SQL Databases

SQL databases store structured data in tables with a clear schema. They are strong choices when the data is relational and transactions matter.

ExamplesPostgreSQL, MySQL, Amazon RDS, Amazon Aurora
Good forOrders, payments, inventory, user accounts
StrengthJOINs, constraints, ACID transactions

NoSQL Databases

NoSQL databases are often designed for flexible schemas, high-scale reads and writes, and simple key-based access patterns.

ExampleAmazon DynamoDB
Good forSessions, carts, likes, counters, event data
StrengthHorizontal scale and low-latency key lookups

Decision Questions

Relationships?If data needs JOINs, SQL is often safer.
Transactions?If multiple writes must succeed or fail together, SQL is strong.
Access pattern?If reads are simple key lookups at massive scale, NoSQL can fit well.
Schema?If the schema changes often, NoSQL may be more flexible.

AWS Mapping

Relational transactions -> Amazon RDS or Aurora
High-scale key-value    -> Amazon DynamoDB
Repeated fast reads     -> ElastiCache
Search queries          -> OpenSearch
Object storage          -> S3

Interview Sentence

"I would choose SQL for relational data, joins, and strong transactions. I would choose NoSQL for high-scale, low-latency, key-based access patterns where the queries are known upfront."

Must-Memorize Q&A

Concepts You Should Be Able to Say Out Loud

What is a monotonic stack?

A stack that keeps items in an increasing or decreasing order so previous unresolved values can be answered efficiently.

Why does Daily Temperatures store indexes?

Because the answer is the number of days waited, which is calculated with current_index - previous_index.

Why is Daily Temperatures O(n)?

Each index is pushed once and popped at most once.

When should you choose SQL?

When the data is relational, needs joins, has a clear schema, or requires strong transactions.

When should you choose NoSQL?

When the system needs high-scale, low-latency, key-based reads and writes with known access patterns.

What is the AWS NoSQL service to remember?

Amazon DynamoDB.
