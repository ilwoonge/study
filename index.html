Concepts

Big-O와 자료구조 감각

Big-O는 입력 크기 n이 커질 때 실행 시간이 어떤 속도로 증가하는지 나타내는 표기법이다.

Big-O Quick Map

O(1) 입력 크기와 상관없이 거의 일정한 시간
O(n) 입력을 한 번 훑는 시간
O(n log n) 보통 정렬에서 나오는 시간

Array Index Access

Array는 연속된 메모리에 저장된다. index를 알면 주소를 바로 계산할 수 있어서 접근 시간이 O(1)이다.

10 20 30 40 
address = base + index * element_size

HashMap Lookup

HashMap은 key를 hash function에 넣어 저장 위치를 계산한다. 그래서 lookup과 insert는 평균적으로 O(1)이다.

"apple" -> bucket 7

최악의 경우 collision 때문에 O(n)일 수 있지만, 면접 풀이에서는 보통 평균 O(1)로 계산한다.

Array vs HashMap

Need Good Choice Why
Index access Array 주소를 바로 계산한다.
Value lookup HashMap / Set 평균 O(1)에 존재 여부를 확인한다.
Count frequency HashMap key별 count를 저장한다.

LeetCode 1

Two Sum

핵심 질문은 "현재 숫자와 더해서 target이 되는 값을 이전에 봤는가?" 이다.

HashMap 풀이

Time O(n) / Space O(n) 
def two_sum(nums, target):
    seen = {}

    for i, num in enumerate(nums):
        need = target - num

        if need in seen:
            return [seen[need], i]

        seen[num] = i

seen에는 숫자를 key로, index를 value로 저장한다. 현재 값을 저장하기 전에 필요한 값이 이미 있는지 먼저 확인해야 자기 자신을 두 번 쓰지 않는다.

LeetCode 2

Contains Duplicate

index나 count가 필요하지 않고 존재 여부만 필요하면 Set을 쓰는 것이 자연스럽다.

Set 풀이

Time O(n) / Space O(n) 
def contains_duplicate(nums):
    seen = set()

    for num in nums:
        if num in seen:
            return True

        seen.add(num)

    return False

HashMap vs Set

Two Sum은 index가 필요하기 때문에 number -> index를 저장하는 HashMap이 맞다. Contains Duplicate은 이전에 본 적 있는지만 알면 되기 때문에 Set이 충분하다.

Interview Sentence

"To detect duplicates, I keep a Set of previously seen numbers. For each number, I check whether it already exists in the Set. Since Set lookup and insertion are average O(1), the total time complexity is O(n), and the space complexity is O(n)."
